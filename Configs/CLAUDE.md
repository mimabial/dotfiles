# CLAUDE.md

Guidance for Claude Code when working in this home directory.

## Core Rules

- Understand the problem fully before writing code.
- Prefer small, coherent changes. Do not add new code smells; fix nearby existing ones when you touch the area.
- Read the existing implementation first and follow local patterns unless there is a strong reason not to.
- If you are unsure about syntax, flags, config keys, or API details, verify them with local help, man pages, or official documentation before editing.
- Verify the changed path before considering the task done.
- Keep code fast and efficient: no redundant processes, polling, or eager loading. Batch work and load on demand.
- Keep the line count low: build on existing primitives and prefer the smaller correct design, including when porting.
- Write self-documenting code: names and structure carry the meaning; a comment only states reasoning the code cannot.

**Reading these files is safe and encouraged** — do it to understand how things work before editing.

Two unrelated manifests exist; do not treat them as interchangeable:

| Manifest | Read by | Describes |
| -------- | ------- | --------- |
| `~/.local/lib/hypr/service/refresh.manifest.psv` | `service/show-managed-split.sh`, `service/managed.sh` | `domain\|layer\|kind\|mode\|backup\|relative-path` — the restore/refresh domains (`hypr-config`, `hypr-state`, `hyprlock`, `hypridle`, `rofi`). `mode` drives refresh/restore (`preserve`/`overwrite`/`sync`/`trash`); every current entry is `preserve` with `backup=never` |

`show-managed-split.sh` only knows the paths listed in `refresh.manifest.psv`, so "No manifest entries matched" means *not a refresh domain* — it says nothing about whether a path is dotfiles-tracked. Check `dotfiles-sync.conf` (or `dotfiles-sync --list`) for that.

## System Architecture

### Component Stack

| Component      | Purpose                          | Config Location          |
| -------------- | -------------------------------- | ------------------------ |
| **Arch Linux** | Base OS                          | `/etc/`, `~/.config/`    |
| **Hyprland**   | Wayland compositor/WM            | `~/.config/hypr/`        |
| **Quickshell** | Active status bar and popups     | `~/.config/quickshell/`  |
| **Rofi**       | App launcher / menus             | `~/.config/rofi/`        |
| **Dunst**      | Notifications                    | `~/.config/dunst/`       |
| **pywal16**    | Color generation from wallpapers | `~/.cache/wal/`          |
| **hyprshell**  | Script runner / entrypoint       | `~/.local/bin/hyprshell` |

The compositor config is **Lua**, not hyprlang `.conf` (a Hyprland Lua plugin evaluates it and exposes a global `hl`: `hl.config`, `hl.env`, `hl.bind`, `hl.window_rule`, `hl.on`, `hl.dsp.*`). `~/.config/hypr/hyprland.lua` is the entry point and loads modules in this order:

1. **Shared core** — `require("core")` (`core.lua`: global `hl.config` defaults, env exports, animation curves, startup `hl.on("hyprland.start")`); `core` pulls in `vars.lua` (static defaults + `vars.get`/`vars.set`) and `runtime.lua` (`runtime.load`).
2. **Theme/runtime** — `themes/theme.lua` (generated; `vars.set`s CURSOR_THEME/FONT/…), `userfonts.lua`, `gpu.lua`, `$XDG_STATE_HOME/hypr/animations.lua`, `$XDG_STATE_HOME/hypr/shaders.lua`.
3. **User overrides** — `windowrules.lua`, `userprefs.lua`, `keyboard.lua` (optional).
4. **Look & Feel** — `$XDG_STATE_HOME/hypr/looknfeel.lua` (optional; written by `window/looknfeel.sh`, see `window/LOOKNFEEL.md`). Deliberately **last of the visual layers**, so panel edits win over both the theme pack and hand-written prefs.
5. **Cursor** — `hl.env` XCURSOR/HYPRCURSOR and `cursor.enable_hyprcursor` are set *after* Look & Feel, so its per-theme `CURSOR_*` variables feed the same path as the theme pack's defaults. `enable_hyprcursor` is computed: a theme with no `manifest.hl` stays on xcursor.
6. **Keybindings** — `keybindings.lua`.
7. **Monitors/state** — `monitors.lua`, `$XDG_STATE_HOME/hypr/monitor-toggles.lua`, `$XDG_STATE_HOME/hypr/window-layout.lua`, `$XDG_STATE_HOME/hypr/workflows.lua`.
8. **Workspaces** — `workspaces.lua`.
9. **Generated monitor rules** — `hyprmoncfg-monitors.lua`, `dofile`d dead last so nothing before it can override the applied layout.

User overrides load after the shared/theme layers, so they win on conflicts. `themes/colors.lua` (generated palette) is loaded from within `core.lua`. Use `hyprshell service/show-managed-split.sh` to inspect which paths are managed vs user-owned, within the refresh domains it covers.

Separate daemons keep their own hyprlang `.conf` files (not the Lua system): `hypridle.conf`, `hyprlock.conf`, `auto_theme.conf`, and `hyprlock/colors.conf`.

**Key behaviors:**

- Hyprland auto-reloads on config save (no restart needed for most changes)
- Use `hyprctl reload` to force reload
- Use `hyprctl configerrors` to check for syntax errors before reload
- `hyprctl keyword` is **rejected** here ("can't work with non-legacy parsers. Use eval."). Apply a keyword live via `hypr_lua_apply 'hl.config({section = {key = value}})'` (defined in `core/common.sh`, after sourcing `runtime/init.bash`), or directly with `hyprctl eval 'hl.config({...})'` (returns `ok`) or `hyprctl dispatch "(function() hl.config({...}); return hl.dsp.no_op() end)()"`. `getoption`/`reload`/`configerrors` all work normally.
- **`hyprctl getoption -j` signals a value's type by which field it emits**, so read the field, don't assume `int`:

  | field | example |
  | ----- | ------- |
  | `int` | `getoption general:border_size` → `{"option": "general:border_size", "int": 2, "set": true }` |
  | `float` | `decoration:active_opacity` → `"float": 0.900000` |
  | `bool` | `decoration:blur:enabled` → `"bool": true` |
  | `str` | `general:layout` → `"str": "master"` |
  | `css` | `general:gaps_out` → `"css": "7 7 7 7"` (custom types; four edges, normalize to a scalar yourself) |

  `set` means the key is set *somewhere in config* — the theme layer counts — so it separates configured from Hyprland's compiled-in default, **not** your override from the theme's. To know which keys a given layer owns, read that layer's Lua.

  Keys are **not** gated by the active layout — `dwindle:preserve_split` resolves normally while `general:layout` is `master`. But not every key in the Hyprland wiki exists in the installed build (`dwindle:pseudotile` is gone; `pseudo` is a dispatcher, not an option), so probe before relying on one.

  `hyprctl -j --batch "getoption a ; getoption b"` does not abort on a bad key. It emits one chunk per command, blank-line separated, and a failed chunk is a bare non-JSON line — either `no such option` or `invalid type (internal error)` (e.g. `group:groupbar:font_weight_active`). Split on the blank line and skip anything that does not parse as JSON.

  Per-leaf animations (`animations:windows`) are keywords, not options, and `getoption` cannot enumerate them — read `core.lua` and `$XDG_STATE_HOME/hypr/animations.lua` for those.
- **`hyprctl dispatch` takes Lua, not legacy dispatcher strings.** Its argument is wrapped as `hl.dispatch(<arg>)`, so `hyprctl dispatch "togglefloating address:0x…"` fails with a Lua syntax error. Use the `hl.dsp.*` form with a `window` selector:

  ```bash
  hyprctl dispatch 'hl.dsp.window.float({action = "toggle", window = "address:0x…"})'
  hyprctl dispatch 'hl.dsp.focus({window = "address:0x…"})'   # focus by selector; hl.dsp.focus({direction=…}) also works
  hyprctl dispatch 'hl.dsp.exec_cmd("kitty")'
  ```

  Enumerate what exists with `hl.dsp` / `hl.dsp.window` (both tables) rather than guessing dispatcher names. Note `hl.get_active_window()` reads focus *at call time* — focus can move between two `hyprctl` invocations, so a helper that acts on the active window may hit a different window than the one you just focused. Pass an explicit selector when it matters.

### Theme Pipeline

- Theme mode uses the selected theme pack's bundled palette.
- Wallpaper mode derives colors via `pywal16`.
- Theme and wallpaper changes are coordinated operations: generate colors, write outputs, reload affected apps, and refresh desktop state.
- Keep non-visible work off the critical path where possible.

Renderers are enumerated by `~/.local/bin/hypr-theme`, which runs every executable,
non-`_`-prefixed file in `render/` in parallel against `active-palette.json`. **A renderer
is enabled by its exec bit** — clearing it silently drops that app from theming.

In theme mode each renderer also picks up a per-pack override: `render_init <app> <out>
[<basename>]` (`render/_lib.sh`) looks for `~/.config/hypr/themes/<pack>/<basename>`,
defaulting to `<app>.theme`, and feeds it in as `PACK_OVERRIDE`. That is what the
`*.theme` files in each pack are for, and why `theme/color.targets.sh` skips the
renderer-owned basenames instead of materializing them (its skip list is literal:
`hypr` `kitty` `rofi` `quickshell` `alacritty` `tmux` `dunst` `wlogout`, so a pack
`*.theme` for any other renderer falls through to the target-path path and warns). `render/dunst.py` does the same in Python via
`load_pack_overrides()`. `render/chrome.sh` opts out by passing `nonexistent.theme`.

Each `<app>.theme` is written in that app's own config syntax, so the renderer can mostly
pass it through — `kitty.theme` is kitty conf, `rofi.theme` is rasi, and
**`quickshell.theme` is a flat JSON `{role: "#hex"}` object**, matching the `theme.json`
the renderer emits. The roles are the ones `shell.qml`'s `role()` reads (`bg`, `fg`, `br`,
`accent`, `act_*`, `alt_*`, `hvr_*`, `c0`–`c15`, `info`/`warning`/`error`/`success`, plus
`background`, `foreground`, `fg_selected`). A pack override that is missing or unparseable
falls through to the palette-derived defaults rather than failing the render, so both
paths yield the same key set.

### Quickshell Bar

Quickshell is the bar. Read `~/.config/quickshell/README.md` before bar work; it
documents the live layouts, style cascade, drawer/popup behavior, and
verification path.

The short version:

- `layouts/<layout>.json` defines composition. `main`, `alt`, `left`, and `sidebar`
  are ordered vertical arrays; `top` and `winbar` use `left`/`center`/`right` arrays.
  `main` and `alt` both render through `MainBar` on the right edge.
  A module entry's `props` object is assigned onto the loaded item by name, so a
  bad key cannot fail statically — the bar warns `unknown bar module prop: <id>.<key>`
  at load instead. The membership test is `key in item`; `item[key] === undefined`
  false-positives on an unset `property var`.
- `styles/base.json` is shared and `styles/<layout>.json` recursively overrides it.
  Rules are keyed by `css`. Static appearance belongs in JSON; runtime-dependent
  color belongs in QML.
- `shell.qml` watches state and selects `MainBar`, `TopBar`, or `WinBar`. The state
  key is `QUICKSHELL_LAYOUT_NAME` in `staterc`.
- Change layouts through `hyprshell quickshell/layout`; it discovers JSON files
  and uses locked `state_set`, so no restart is needed.
- `ScriptButton` reads `{text, class, tooltip}` provider output. Script providers
  under `sysinfo/` and elsewhere emit that shape.

Only one popup is open globally. Popup keyboard focus is intentionally primed
with `Exclusive` and then reduced to `OnDemand`; bars use `None` while closed so
clicking outside a popup reaches the target window on the first click. Preserve
that sequence.

`dock/`, `expose/`, `monitor/` and `cliamp/` are standalone panels, not bar layouts:
they run alongside whichever layout is active and reach the shared palette through the
`qs.Commons` shim rather than `Theme.qml`. `dock/` and `expose/` are Omarchy plugin
ports; `monitor/` is the display/topology editor. `dock/` and `expose/` each carry their
own `settings.json`; `monitor/` does not. The per-panel `README.md` files are gone —
`~/.config/quickshell/README.md` is the only one left.

Keep the bar service-manager agnostic. QML and helpers must not call `systemctl`.
The current unit only supervises `/usr/bin/quickshell`; runit can supervise the
same command later.

### State Management

### Host Profiles

The dotfiles sync system is host-aware. The active profile is stored at `~/.local/state/hypr/host-profile` (e.g. `laptop`). `~/.config/hypr/dotfiles-sync.conf` marks files with `host|...` for per-host storage and `dir|...|excludes` for shared dirs with generated/per-host exclusions.

Manage profiles with `dotfiles-host-profile show|list|set <profile>|apply [--dry-run]`.

## Common Commands

```bash
# Switch theme
hyprshell theme.switch.sh -s "<Theme Name>"

# Import an omarchy theme (dir or git URL) as a theme pack; --dry-run prints only
hyprshell theme/theme.import <source> [--name X] [--icons X] [--cursor X] [--size N] \
                                      [--nvim X] [--kvantum flat|materia|pill] [--dry-run] [--force]

# Rotate wallpaper and regenerate colors (next/previous/random are subcommands,
# --global is the flag; there is no -n)
hyprshell wallpaper next --global

# Validate and reload Hyprland
hyprctl configerrors
hyprctl reload

# Query hyprlang .conf/.meta files ONLY (hypridle/hyprlock/auto_theme, themes/*.meta,
# hyprlock/colors.conf). It does NOT parse the Lua compositor config — read those .lua
# files directly. Usage: hyq -Q '<query>' <file>
hyq -Q '$CURSOR_THEME' ~/.config/hypr/themes/theme.meta

# Select or set the active Quickshell layout
hyprshell quickshell/layout select
hyprshell quickshell/layout set left

# Soft Quickshell reload (reuses the engine; see "Reload Behavior")
quickshell ipc call bar reload

# Switch workflow profile. Selectable: default, editing, windows.
# gaming and powersaver exist but are automatic (GameMode / power-saver profile)
# and are excluded from the picker; while one owns the workflow, --set fails.
hyprshell util/workflows --select

# Switch animation preset / shader
hyprshell animations.sh
hyprshell shaders.sh

# Auto-theme (light/dark by location/time) — daemon control
auto-theme {start|stop|status|toggle}

# Host profile management (drives dotfiles-sync host-specific entries)
dotfiles-host-profile show
dotfiles-host-profile set <profile>
dotfiles-host-profile apply [--dry-run]

# Inspect the managed/generated split for refresh-domain paths (reads
# refresh.manifest.psv — NOT dotfiles-sync.conf, and it knows nothing about hosts)
hyprshell service/show-managed-split.sh [path...]

# Check whether a path is mirrored into ~/dotfiles/ (reads dotfiles-sync.conf)
dotfiles-sync --list

# Sync the active xkb layout across keyboards (layout set is kb_layout="us,fr")
hyprshell util/keyboard-switch.sh

# Audit fonts not referenced by config, and optionally remove them
```

## Reload Behavior

| Component | Auto-reloads on save? | Manual reload command                        |
| --------- | --------------------- | -------------------------------------------- |
| Hyprland  | Yes                   | `hyprctl reload`                             |
| Quickshell | Yes; data is also watched in place | `quickshell ipc call bar reload`       |
| Dunst     | **No**                | `dunstctl reload`                            |
| Rofi      | Yes (per-launch)      | N/A                                          |
| Hypridle  | **No**                | restart it through the active supervisor     |
| `start.*` watchers | **No**       | restart the actual running process/unit      |

Quickshell layout, style, state, theme, and font files are watched in place.
Source QML normally triggers Quickshell's own reload; use the IPC command for a
verification run. Popup-only errors may appear only after opening the affected
popup.

`bar reload` is `Quickshell.reload(false)` — a **soft** reload that reuses the
running engine and keeps existing instances, so it does not reliably pick up a
changed `vars.lua` value or a re-evaluated `font.family`. When a change appears
to do nothing, restart the process before concluding the change was wrong. A
newly installed font always needs a real process restart: Qt builds its font
database once per process, and no reload rebuilds it.

Many daemons currently started via `start.*` (`vars.lua`) run as systemd user units. `hyprshell app
-u <name>.service -t service …` gives exactly `<name>.service` (`hyprland-submap-hint`,
`hyprland-wallpaper`); without `-u` it is a transient app2unit
unit named `app-Hyprland-<name>@<id>.service`, not the packaged `<name>.service`. Target
the running unit, or use the daemon's own reload where it has one.

These load their Python/shell once at startup, so editing a script under
`~/.local/lib/hypr/` changes nothing until the unit restarts — and a fresh `python3`
run will show the fix while the live daemon still serves the old code:

```bash
systemctl --user restart hyprland-submap-hint.service   # e.g. after editing keybinds/lib/
```

That describes the current host, not an implementation requirement. Prefer a
daemon's own control interface where available, and do not introduce new
systemd-only dependencies; this configuration is expected to move to runit.

For simple changes, edit files in `~/.config/`:

### Pattern 2: Keybinding Changes

Keybindings live in `keybindings.lua` (Lua, not `.conf`). The file defines local helpers over `hl.bind`: `bind(mods, key, description, dispatcher, opts)` and `exec(mods, key, description, command, opts)` (dispatchers come from `hl.dsp.*`, e.g. `hl.dsp.window.fullscreen({...})`, `hl.dsp.exec_cmd(cmd)`).

**The convention — follow it, do not add exceptions:**

| chord | meaning |
| ----- | ------- |
| `mod` | the primary action for that key, or a submap leader |
| `mod SHIFT` | the other/stronger version of that same key's action |
| `mod ALT` | the same action, without following the window |
| `mod CTRL` | relative/scoped navigation |

Function, XF86, mouse and `Print` keys are a hardware class and sit outside the convention.

**Never bind punctuation.** `input:resolve_binds_by_sym = true` (`userprefs.lua`) resolves binds against the **active layout's level-1 keysym** with modifiers zeroed. AZERTY puts `.` `/` `[` `]` above level 1, so those binds are silently unreachable in the `fr` layout — not remapped, just dead. Letters always exist at level 1 in both layouts, so use letters and submaps. Verify a new bind with `xkbcli how-to-type --layout fr '<char>'`.

**Submaps** give each domain its own key namespace (`hl.define_submap(name, fn)`). Eight leaders: `mod+W` window, `mod+T` theming, `mod+O` open, `mod+J` terminal, `mod+R` capture, `mod+I` insert, `mod+H` hints, `mod+U` utilities. Helpers:

- `submap_leader(name, mods, key, body)` — defines the submap and its leader; adds `ESCAPE` to exit.
- **Leave-then-act:** `submap_action(key, desc, dispatcher)` and its exec wrapper `submap_exec(key, desc, command)`. **Use these for anything that opens rofi** — inner binds are bare keys and would otherwise swallow rofi's input.
- **Stay in the submap:** `submap_stay_action(key, desc, dispatcher, opts)` / `submap_stay_exec`, and the `{repeating = true}` pair `submap_repeat_action` / `submap_cycle`. For repeat actions that never open a picker.

Both families record the bare dispatcher in `bind_actions[description]`, which is what lets `keybinds_hint` run the action without entering the submap.

Invariants that are easy to break:

- **Descriptions are lookup keys.** `keybinds_hint.py` base64s the description into `HYPR_BIND_ACTIONS[description]`, which `keybinds_hint.sh` dispatches. Keep them unique and stable.
- **A submap leader is found by its `[Submap] ` description marker**, not by hyprctl. The Lua plugin reports every bind as dispatcher `__lua`, so `hyprctl binds` never reports `submap`. The marker string is duplicated in `keybinds_hint.py`; change both together.
- **`[Hidden] ` is the same kind of marker**, for binds a submap re-exposes from the global set: they work inside the submap but stay out of its hint. Duplicated as `HIDDEN_MARKER` in `keybindings.lua` and `keybinds/lib/submap_hint.py`; change both together.
- **`{locked = true}` binds work on the lock screen** and cannot move into a submap (the leader is unreachable there). `mod K` (keyboard layout) depends on this.
- **`layout_action(layout, …)` gates the dispatch, not the bind.** The bind registers unconditionally; the layout check runs at press time inside the Lua closure, which hyprctl cannot see. So the sub-category header must name the layout — `[Window Mode|Scrolling]` for `layout_action("scrolling", …)` — because `LAYOUT_HEADERS` in `keybinds/lib/submap_hint.py` filters the hint on that header. A mismatch shows a bind that silently no-ops, or hides a working one.

**When re-binding an existing key:**

1. Find the existing binding: `grep -n '"F"' ~/.config/hypr/keybindings.lua`
2. **Edit that entry's dispatcher in place** — do not add a second `bind`/`exec` for the same chord (duplicates stack, they don't replace). `hl.unbind(chord)` exists but is not used here.
3. Inform the user what the key was previously bound to.

```lua
-- was: bind(mod, "F", "[Window Management] toggle fullscreen", hl.dsp.window.fullscreen({mode = "fullscreen", action = "toggle"}))
exec(mod, "F", "[Launcher|Apps] file manager", "nautilus")
```

Verify with `hyprctl configerrors`, then diff the live set against the intent.
`hyprctl binds -j` is unusable here — it exits 5 and emits field/value-misaligned
JSON — so parse the plain output instead (this lists described binds only, which is
every bind declared in `keybindings.lua`):

```bash
hyprctl binds | awk '/^\tmodmask:/{m=$2} /^\tsubmap:/{s=$2} /^\tkey:/{k=$2} /^\tdescription:/{sub(/^\tdescription: /,"");print m"\t"k"\t"s"\t"$0}' | sort
```

### Pattern 3: Window Rules

Window rules live in `windowrules.lua` as `hl.window_rule({...})` calls. Before writing any, check the existing entries and follow their structure exactly:

```lua
hl.window_rule({["match"] = {["class"] = "^(kitty)$"}, ["opacity"] = "0.80 override 0.80 override 1"})
```

### Pattern 4: Reset to Defaults

When customizations go wrong, the service scripts can restore managed configs:

```bash
# Restore one managed config file from ~/.local/share/hypr/default/
hyprshell service/config.sh --mode restore <relative-path-under-config>

# Restore whole managed domains from stock defaults (backs up first)
hyprshell service/managed.sh --mode restore <domain> [domain...]
```

## Working Workflow

- Read the relevant files before editing.
- Prefer existing helpers and shared libraries over one-off logic.
- For direct Hypr shell script runs, source `~/.local/lib/hypr/runtime/init.bash` to bootstrap `LIB_DIR`, `HYPR_*_HOME`, and lock paths before invoking helpers.
- If a live config change should persist, sync it back into `~/dotfiles/` after editing the live file(s). Per-host changes are routed by the active `host-profile`.

## Script Conventions

- Bash: use `[[ ... ]]`, quote paths, and prefer explicit fallback handling.
- Use absolute paths for config and state references where practical.
- Keep functions small and composable.
- Avoid backgrounding long-running work unless the path is already lock-safe.
- Comments explain the reasoning behind the code, not what it does. Keep them concise and meaningful; never duplicate what the code already says.

## Verification Expectations

**Where verification stops.** The list below is a ceiling, not a floor. Each item is
checked once, and the result stands.

- Verify a result once. Do not re-run a command or take a second screenshot to
  re-confirm something already measured.
- A change that mirrors an already-verified pattern — a width copied from a sibling
  popup, a one-line constant, a rename — needs no run of its own. Name what it
  matches instead.
- Screenshots are for what cannot be observed any other way: an unfamiliar layout, a
  visual bug, a change with no log output. Never to confirm an edit landed; the edit
  tools already report that.
- When a check is genuinely unavailable here (no synthetic input, absent hardware),
  say so once and move on. Do not substitute three weaker checks for the one missing.
- Verification is not progress. Report the outcome, not the act of checking.

- For Bash changes: run `bash -n` on touched scripts.
- For Zsh changes: run `zsh -n` on touched functions/completions.
- For Hyprland config changes: run `hyprctl configerrors` before reload.
- For theme pipeline changes: exercise `hyprshell theme.switch.sh` or `hyprshell wallpaper next --global` as appropriate and inspect generated outputs.
- For Quickshell QML changes: lint touched files, force a reload, and inspect only the new log output. Open changed popups during verification.
  - **Use `/usr/lib/qt6/bin/qmllint`, not bare `qmllint`.** `$PATH` resolves to the qt5-declarative build, which resolves no types and exits 0 on anything that merely parses — it passed `Item { property int x: undefinedThing.foo }`. The Qt6 binary catches that.
  - Pass import paths or it resolves nothing: `-I /usr/lib/qt6/qml -I ~/.config/quickshell -I ~/.cache/qmllint`. The last one holds a `qs` symlink to the config root (`ln -sfn ~/.config/quickshell ~/.cache/qmllint/qs`); without it every `import qs.Commons` fails and the file's members go unchecked.
  - `Type PanelWindow is not creatable` (Quickshell types) is pre-existing noise, not your change. Filter it, then compare what is left against an untouched neighbour file.
  - Every directory of QML declares its types in a `qmldir` (root, `modules/`, `dock/`, `expose/`, `cliamp/`, `monitor/`, `monitor/Ui/`, `Commons/`, `Ui/`), so `Style` and the other singletons resolve and a wrong member is a real finding. **Add a new component to its directory's `qmldir`** — with a qmldir present, an undeclared file is not a type, and lint stops resolving it.
  - `qs` maps to the config root, so `qs.Commons` is `~/.config/quickshell/Commons`. A root-level file that imports `qs.Commons` unqualified gets *two* `Style` types in scope — the module's and the root's, which is a facade over it exposing a different member set. Import it as `import qs.Commons as Commons` and qualify the uses, the way `MediaPopup.qml` and the `expose/`/`cliamp/` files do; unqualified, lint and the runtime disagree about which `Style` wins.
  - **`pragma ComponentBehavior: Bound` is on 84 of the 224 QML files, all of which lint free of `[unqualified]`, and must stay that way.** It is what lets a delegate reach outer ids, and it is why those files report no `[unqualified]`. Under it, an unqualified access is a **runtime break, not a style nit**: `RotationAnimator { running: visible }` in `cliamp/TrackList.qml` resolved to `[undefined]`, and `BluetoothPopup.qml` threw `property of null` across its whole device list. Both were silent until the view had data.
  - So the rule is: **add the pragma only to a file lint reports clean, and if adding it leaves any `[unqualified]`, either qualify every one or leave the pragma off.** The 29 files still carrying `[unqualified]` deliberately have no pragma; do not add one without clearing them first. The rest of the non-pragma files are already `[unqualified]`-free and are simply candidates. Delegates that read `modelData`/`index` must declare `required property var modelData` / `required property int index` — under the pragma, context injection no longer reaches them.
  - Lint cannot prove a delegate works: it only sees the file. A view whose model is empty at reload renders nothing, so a broken delegate leaves a clean log. Exercise it with data — instantiate the component against a mock model through `quickshell -p <a throwaway .qml inside the config dir>` (the config root must be the real one, or `qs.*` will not resolve) and diff the warnings against the same run on the pre-change file. A bare Qt harness is the opposite: `qmlscene`/`qml` must run the throwaway from **outside** the config dir, since the implicit same-directory import drags in every type there and dies on `module "Quickshell" plugin "quickshell-coreplugin" not found`. Use that for probes needing no `qs.*` (plain QML semantics, property checks).
  - **Qt swallows QML console output unless you ask for it:** `QT_ASSUME_STDERR_HAS_CONSOLE=1 QT_FORCE_STDERR_LOGGING=1 QT_QPA_PLATFORM=offscreen /usr/lib/qt6/bin/qmlscene <file>`. Without those, `console.log`/`print` produce nothing at all and the run just looks silent; `QT_LOGGING_RULES="*.debug=true"` does not fix it.
  - `Repeater` only creates **Items**. For non-Item delegates (a `Process`, say) use `Instantiator` — a `Repeater` silently creates nothing.
  - Lint is not the real check. Reload and read the log: `quickshell ipc call bar reload`, then `journalctl --user --since "10 seconds ago" | grep -iE 'WARN|ERROR|TypeError' | grep -v font.db`. The `OpenType support missing` lines are constant background noise.
- For Quickshell layout/style changes: validate JSON with `jq empty` and verify the active layout live.
- For wlogout color changes: run `render/wlogout.sh`, then open the menu with `hyprshell logout-launch.sh 2`.
- For notification changes: prefer dry runs or non-destructive test paths when testing stateful behavior.
