# Keyboard layouts

This machine runs two layouts, `us` and `fr`. `Super + K` switches between them,
and it works on the lock screen — which is not a detail, since typing a password
in the wrong layout is exactly when you need to switch.

```bash
hyprshell util/keyboard-switch.sh
```

That syncs the active layout across every connected keyboard, rather than
switching one and leaving the built-in one behind.

`~/.config/hypr/keyboard.lua` holds the layout list. It is generated by the bar's
language module, so change it through the bar popup or
`hyprshell util/keyboard-layout` rather than by hand.

## Why this shapes the whole config

`resolve_binds_by_sym = true` is set in `userprefs.lua`. It means Hyprland
resolves keybindings against the **active layout's level-1 keysym**, with
modifiers zeroed.

On AZERTY, `.` `/` `[` and `]` are not at level 1. So a bind on any of them does
not get remapped when you switch layouts — it silently stops existing. No error,
no warning, just a key that does nothing until you switch back.

That is why there is no punctuation bound anywhere in this config. Letters exist
at level 1 in both layouts. Workspace digits are bound by keycode, which no
layout remaps. And the namespace pressure that would normally push you onto
brackets and slashes is absorbed by eight submaps instead.

Before adding any bind, check it can be typed in both:

```bash
xkbcli how-to-type --layout fr '<char>'
xkbcli how-to-type --layout us '<char>'
```

If it needs a level above 1 in either, pick a different key. This is a rule with
no exceptions in the config, and it is worth keeping that way — the failure mode
is invisible, which makes it the kind of bug you rediscover every six months.

## The indicator

The bar has a language module showing the active layout, so you can tell at a
glance which one you are in before you start typing. On the `winbar` and `top`
layouts it sits on the right; add `language` to any other layout's JSON if you
want it there too.
